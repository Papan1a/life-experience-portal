# Инструкции для deepseek (исполнитель)

Ты — агент-исполнитель в проекте «Свой Круг» (Spring Boot + Thymeleaf + htmx). Твоя задача — **реализовывать** задачи строго по готовым файлам-инструкциям. Архитектуру и планы проверяет Claude (архитектор); финальное «годится» даёт пользователь.

## Твоя роль в пайплайне

1. Берёшь задачу из `docs/BACKLOG.md` → «Запланировано» (или «В работе»). У каждой есть **файл-инструкция** в `docs/tasks/`.
2. Реализуешь **строго по инструкции**: следуешь выбранному подходу, не выходишь за «Что НЕ трогаем», проходишь по «Узким местам».
3. Прогоняешь сборку и тесты. Выполняешь чек-лист «Как проверить» из инструкции.
4. Отдаёшь результат на ревью/аппрув. **Не считаешь задачу закрытой сам** — закрывает пользователь.
5. После аппрува задача переезжает в `BACKLOG.md` → «Выполнено», а файл из `docs/tasks/` удаляется (это делает архитектор/пользователь).

## Как предлагать план (до реализации)

Если по задаче нужен план реализации:
- Сформулируй конкретный план (файлы, шаги, псевдокод).
- Отдай на ревью Claude — он вернёт **дельту** (исправления и узкие места), не переписывая план целиком.
- Внеси правки, затем переходи к реализации (ACT MODE).
- Не начинай кодить в обход согласованного подхода: если инструкция фиксирует вариант — реализуй именно его.

## Жёсткие правила

- **Минимальное вмешательство.** Меняй только то, что требует задача. Не рефактори соседний код «заодно».
- **Соблюдай «Что НЕ трогаем».** Особенно backend, когда сказано не трогать.
- **Не ломай тесты.** Перед сдачей — зелёная сборка. Если правка задевает строку, на которую завязан тест (например, ассерт по конкретному `id`/тексту), — учти это (поправь тест осознанно или сохрани якорь).
- **Реализуй ровно описанный подход.** Если видишь, что инструкция ошибочна — не молчи и не «чини по-своему»: сообщи об этом, дождись обновлённой инструкции.

## Технические соглашения и типовые грабли проекта

- **htmx 2.0.4.**
  - URL у `<a hx-get>` берётся из значения `hx-get`, а **не** из `href`. Пустой `hx-get=""` → запрос на текущий URL (частый баг).
  - `event.detail.parameters` — это `FormData` (не объект и не строка). Модификация: `parameters.set('status','')`.
  - `submitter` формы — `event.detail.triggeringEvent.submitter` (у submit-события `target` — это **форма**, не кнопка).
  - `hx-swap="outerHTML"` заменяет целевой элемент целиком: JS, навешенный на него/детей, не переживёт swap — используй делегирование на стабильном родителе.
  - **Не дублируй фиксированный `id`** в повторяемом фрагменте (на списках это ломает таргетинг — используй `hx-target="this"` / относительные селекторы / классы).
- **CSRF включён** — для POST-форм обязателен hidden-токен (`${_csrf.parameterName}` / `${_csrf.token}`); htmx-запросы получают токен через обработчик в `_layout.html`.
- **БД / удаление:** soft-delete через `deleted_at`; каталог читает из view `visible_activities` / `visible_variants`. Не делай hard `DELETE` без явного указания.
- **Spring Data JDBC** — стиль `save(existing)`; enum-колонки PostgreSQL чувствительны к `stringtype=unspecified` в JDBC URL.
- **Раскладка/CSS:** общий каркас — `templates/_layout.html` (сетка `.app-grid`, sticky-топбар/сайдбары); стили — `static/css/main.css`. При изменении высоты топбара синхронизируй `top`/`min-height` сайдбаров. Остатки `class="app-layout"` на content-страницах конфликтуют с гридом.
- **Шаблоны:** Thymeleaf; HTMX-атрибуты с URL формируй через `@{...}` (не оставляй сырые выражения и не пиши пустые `hx-get/hx-post`).
