# Issue #26 — Раскладка чипсов-категорий: минимизировать число строк

## Что нужно

На главной (вкладка «Каталог активностей») чипсы категорий сейчас занимают **три строки**, хотя при текущей ширине 2-й колонки места хватает на **две**. Нужно изменить раскладку так, чтобы стремиться к минимальному числу строк.

## Контекст

- Разметка: [catalog/index.html:16-30](src/main/resources/templates/catalog/index.html#L16-L30) — `<div class="chips">` с чипсом «Все» + `th:each` по `${categories}`. Порядок категорий = порядок из `categoryRepository.findAllActive()` ([CatalogService.getAllCategories](src/main/java/com/lep/portal/catalog/CatalogService.java#L37)).
- Стили: [main.css:616-627](src/main/resources/static/css/main.css#L616-L627):
  ```css
  .chips { display: flex; flex-wrap: wrap; gap: 5px; }
  .chip  { padding: 4px 10px; gap: 6px; font-size: 0.85rem; ... }
  .chip-icon { width: 18px; height: 18px; }
  ```

Чипсы уже компактные (padding/gap небольшие). Перенос на 3 строки при достатке места на 2 обычно вызван либо суммарной шириной чипсов чуть больше двойной ёмкости строки, либо неудачным порядком (длинные ярлыки кучно).

## Подход

Это чисто визуальная подгонка. Действовать по нарастанию вмешательства, остановиться на минимально достаточном:

1. **Сначала измерить** в DevTools: сколько категорий, какова суммарная ширина чипсов и ширина 2-й колонки. Понять, насколько «не помещается» в 2 строки.

2. **Уменьшить габариты чипса** (самый простой и предсказуемый путь):
   - чуть уменьшить горизонтальный `padding` (`4px 10px → 4px 8px`),
   - уменьшить внутренний `gap` иконка↔текст (`6px → 4px`),
   - при необходимости `font-size 0.85rem → 0.82rem` и/или `chip-icon 18px → 16px`.
   Этого обычно достаточно, чтобы строки сложились в 2.

3. **Если всё равно три строки** — пересмотреть **порядок категорий** (прямое предложение из issue). Порядок задаётся в БД/репозитории. Варианты:
   - отсортировать категории так, чтобы короткие ярлыки чередовались с длинными (лучше укладка),
   - либо задать явный `display_order` в `categoryRepository.findAllActive()` (если в таблице категорий есть поле сортировки — проверить; если нет, не вводить миграцию ради косметики, ограничиться CSS).

4. Не уходить в сложные решения (CSS grid с фиксированными колонками и т.п.) — задача косметическая.

## Узкие места

- **Адаптивность:** при сужении окна 3 строки — это нормально; цель — 2 строки на типовой десктопной ширине 2-й колонки. Проверить на разных ширинах, не делать хуже на узких.
- Чипсы — кликабельные ссылки-фильтры; уменьшая размер, **сохранить кликабельность и читаемость** (не делать слишком мелким).
- `.chip.active` (зелёный фон) не должен ломать раскладку — проверить активное состояние.
- Иконки `image-rendering: pixelated` — при уменьшении следить за чёткостью.

## Что НЕ трогаем

- Логику фильтрации по категориям, ссылки `th:href`.
- Backend (если не вводим `display_order` — а его вводить не нужно ради косметики).

## Как проверить

1. На главной чипсы укладываются максимум в 2 строки при типовой ширине экрана.
2. Чипсы читаемы и кликабельны, активная категория подсвечена.
3. На узком экране раскладка переносится корректно, без обрезаний.
