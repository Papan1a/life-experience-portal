# Issue #24 — Ошибка 400 при вводе тегов на форме создания активности

## Симптом

На странице `localhost/activities/new` при вводе текста в поле **«Теги (через запятую)»** в процессе ввода всплывает ошибка: **«⚠️ Запрос не выполнен (400)»**.

## Контекст

Проект — Spring Boot + Thymeleaf + HTMX. Поле тегов использует HTMX-автодополнение: при наборе текста отправляется фоновый GET-запрос к серверу за подсказками тегов, ответ подставляется в выпадающий список (`<datalist>`).

Ошибка 400 (Bad Request) означает, что сервер отклоняет запрос ещё до обработки — как правило, из-за **несоответствия имени параметра**, которое контроллер ожидает в запросе, и того, что фактически отправляет фронтенд.

## Где смотреть

- **Шаблон формы:** `src/main/resources/templates/catalog/activity_form.html` — блок поля тегов (около строк 103-116). Там настроены HTMX-атрибуты: какой URL вызывается, какой параметр включается в запрос (`hx-include`).
- **Контроллер-обработчик:** `src/main/java/com/lep/portal/catalog/TagController.java` — метод, обрабатывающий запрос автодополнения. Обрати внимание, **как именно назван обязательный параметр запроса** в аннотации параметра метода.

## Что нужно сделать

1. **Сначала диагностируй, не угадывай.** Открой форму в браузере, открой DevTools → вкладка Network, начни вводить текст в поле тегов и поймай фоновый запрос, который возвращает 400. Посмотри:
   - на какой URL идёт запрос,
   - какие query-параметры реально уходят (их имена и значения),
   - что именно в теле ответа 400 (Spring обычно пишет, какого обязательного параметра не хватает).

2. **Сопоставь** имя параметра, который отправляет фронтенд, с именем обязательного параметра, который ожидает метод контроллера. Расхождение здесь — наиболее вероятная причина 400.

3. **Исправь рассогласование.** Привести в соответствие нужно так, чтобы фронтенд отправлял именно тот параметр (с тем именем), который ожидает сервер. Реши, какую сторону менять, исходя из того, что является «правильным контрактом» этого endpoint (имя параметра должно быть осмысленным).

4. Убедись, что после ввода подсказки действительно появляются (endpoint возвращает теги по введённому префиксу), а не просто исчезает ошибка 400.

## Важно

- **Минимальная правка по существу проблемы.** Не переписывай весь механизм автодополнения, не меняй логику поиска тегов на сервере — проблема в контракте «фронт↔сервер», а не в бизнес-логике.
- Не убирай само автодополнение, чтобы «убрать ошибку» — его нужно почивать, а не отключать.
- Проверь, что обычная отправка формы (создание активности с тегами) по-прежнему работает — поле тегов участвует и в сабмите всей формы, не только в автодополнении.

## Как проверить

1. Запусти приложение, залогинься, открой `/activities/new`.
2. Введи в поле тегов несколько букв — ошибки 400 быть не должно, в DevTools запрос автодополнения возвращает 200.
3. Убедись, что в выпадающем списке появляются подходящие подсказки (предварительно в системе должны существовать теги с таким префиксом).
4. Заполни форму целиком и создай активность — теги должны корректно сохраниться.
