# Issue #21 — Снятие отметки повторным кликом (убрать кнопку «Снять отметку»)

## Что нужно

На странице активности (и варианта) есть отметки статуса: **«Интересно»**, **«Хочу попробовать»**, **«Пробовал(а)»**, **«Хочу повторить»**. Сейчас рядом с ними появляется отдельная кнопка **«✕ Снять отметку»**.

Требуется:
1. **Убрать** кнопку «Снять отметку».
2. Снятие отметки должно происходить **повторным кликом по уже выделенной (активной) метке**: кликнул на активную метку → отметка снимается.

## Контекст

Проект — Spring Boot + Thymeleaf + HTMX (**htmx 2.0.4**). Backend для этого **уже полностью готов** — серверную логику менять не нужно:
- Endpoint `/experiences` принимает параметр `status`. Пустое значение `status` → сервер удаляет отметку (снятие). Имя статуса → ставит/меняет отметку.
- То есть «снять отметку» = тот же запрос, но с пустым `status`.

**Файл с разметкой:** `src/main/resources/templates/experience/_status_buttons.html`.

Сейчас там HTMX-форма (`hx-post=@{/experiences}`, `hx-swap="outerHTML"`, `hx-target="#status-buttons"`). Каждая метка — `<button type="submit" name="status" value="...">` с **фиксированным** значением (`INTERESTING`, `WANT_TO_TRY`, `TRIED`, `WANT_REPEAT`). Активная метка отличается классом `btn-primary` (через `th:classappend`), вычисляемым сравнением текущего статуса пользователя со значением кнопки.

## Решение — чистый Thymeleaf, без JavaScript

Ключ: кнопка-submit отправляет пару `name=value` **того элемента, по которому кликнули** (submitter). Если у активной метки через `th:value` выставить пустую строку, то клик по ней отправит `status=` (снятие). Клик по неактивной метке отправит её реальное значение (установка/смена). htmx 2.0 включает значение submitter'а в `FormData`, в том числе пустую строку — поэтому **никакого JS, событий `configRequest`/`triggeringEvent`/`parameters` не нужно**.

> Почему именно так, а не через JS-обработчик в `_layout.html`:
> - `hx-swap="outerHTML"` заменяет сам контейнер `#status-buttons` после каждого клика — любой JS, навешенный на него или его потомков, умер бы. Здесь решать нечего: это просто HTML.
> - Поведение остаётся локальным во фрагменте, а не протекает в глобальный layout.
> - Нет зависимости от внутренностей htmx и его версии.

### Единственное изменение: `src/main/resources/templates/experience/_status_buttons.html`

**Шаг 1.** Удалить блок кнопки «Снять отметку» целиком (сейчас строки 33–39):

```html
<th:block th:if="${userExperience != null}">
    <button type="submit" name="status" value="" ...>✕ Снять отметку</button>
</th:block>
```

**Шаг 2.** Переписать каждую из 4 кнопок: ввести `th:with="active=..."` и заменить статический `value="..."` на `th:value`. Пример для «Интересно»:

```html
<button type="submit" name="status"
        th:with="active=${userExperience != null && userExperience.status.name() == 'INTERESTING'}"
        th:value="${active} ? '' : 'INTERESTING'"
        th:classappend="${active} ? 'btn-primary' : 'btn-secondary'"
        class="btn btn-small">
    ✨ Интересно
</button>
```

То же самое для остальных трёх — везде одинаковая структура (`th:with`, `th:value`, `th:classappend`), меняется только значение статуса и подпись:
- `WANT_TO_TRY` — «🎯 Хочу попробовать»
- `TRIED` — «✅ Пробовал(а)»
- `WANT_REPEAT` — «🔄 Хочу повторить»

## Узкие места — на что обратить внимание

1. **Полностью убрать статический атрибут `value="..."`**, оставив только `th:value`. Не оставляй оба атрибута на одном теге.
2. **`th:with` объявляй на том же `<button>`**, а не на форме. Переменная `active` будет видна в `th:value` и `th:classappend` того же элемента (`th:with` обрабатывается раньше них).
3. Подпись метки (`✨ Интересно` и т.д.) — это **содержимое тега**, оно не зависит от `value`. При пустом `value` подпись и класс `btn-primary` у активной кнопки сохраняются — доступность и вид не страдают.

## Что НЕ трогаем

- **Backend** (endpoint, сервис, репозитории) — пустой `status` уже обрабатывается как снятие.
- **`_layout.html`** — никакого JS не добавляется.
- **`catalog/activity.html` (строка 64) / `catalog/variant.html` (строка 44)** — фрагмент общий, изменения подхватятся автоматически, отдельно править их не нужно.
- **Соседние фрагменты** (bookmark, report) — не затрагиваются.

## Как проверить

1. Запусти приложение, залогинься, открой страницу любой активности.
2. Кликни по метке (например «Интересно») — становится активной, статус сохраняется (проверь после перезагрузки страницы).
3. Кликни по **той же** активной метке ещё раз — отметка **снимается** (после перезагрузки статус пуст).
4. Поставь метку, затем кликни по **другой** метке — выделяется новая, статус сменился (а не снялся).
5. Убедись, что кнопки «Снять отметку» больше нет.
6. Повтори шаги на странице **варианта** активности — фрагмент статусов используется и там.
