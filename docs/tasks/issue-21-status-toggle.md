# Issue #21 — Снятие отметки повторным кликом (убрать кнопку «Снять отметку»)

## Что нужно

На странице активности (и варианта) есть отметки статуса: **«Интересно»**, **«Хочу попробовать»**, **«Пробовал(а)»**, **«Хочу повторить»**. Сейчас рядом с ними появляется отдельная кнопка **«✕ Снять отметку»**.

Требуется:
1. **Убрать** кнопку «Снять отметку».
2. Снятие отметки должно происходить **повторным кликом по уже выделенной (активной) метке**: кликнул на активную метку → отметка снимается.

## Контекст и важная деталь

Проект — Spring Boot + Thymeleaf + HTMX. Backend для этого **уже полностью готов** — менять серверную логику не нужно:
- Endpoint статусов принимает параметр `status`. Если прислать **пустое** значение `status` — сервер удаляет отметку (это и есть «снятие»). Если прислать имя статуса — ставит/меняет отметку.
- То есть «снять отметку» с точки зрения сервера = отправить тот же запрос, но с пустым `status`.

**Файл с разметкой:** `src/main/resources/templates/experience/_status_buttons.html`.

Сейчас там форма с HTMX (`hx-post` на endpoint статусов, замена фрагмента целиком). Каждая метка — это `<button type="submit" name="status" value="...">` с **фиксированным** значением (`INTERESTING`, `WANT_TO_TRY`, и т.д.). Активная метка отличается CSS-классом (primary вместо secondary), вычисляемым через сравнение текущего статуса пользователя с значением кнопки.

## В чём сложность

Обычная HTML-кнопка `submit` всегда отправляет своё статическое `value`. Поэтому «клик по активной метке должен отправить пустой статус вместо своего значения» **нельзя выразить чистым HTML** — нужен небольшой клиентский скрипт, который для уже активной метки подменяет отправляемое значение `status` на пустое.

## Подход (без точной реализации)

1. **Убери** блок с кнопкой «Снять отметку» целиком.

2. Сделай так, чтобы при клике по метке, которая **уже активна** (т.е. соответствует текущему статусу пользователя), на сервер уходило **пустое** значение `status` (снятие). При клике по неактивной метке — её обычное значение (как сейчас).

   Возможные направления (выбери одно, наиболее простое и согласованное с тем, как в проекте уже используется HTMX):
   - Небольшой JS-обработчик, который перед отправкой формы определяет, кликнули ли по активной метке, и если да — очищает отправляемое значение статуса.
   - Либо использовать HTMX-атрибуты на самих кнопках так, чтобы активная метка слала пустой статус. HTMX позволяет задавать значения отправляемых параметров на уровне элемента — изучи `hx-vals` и события HTMX перед запросом.

3. Признак «активности» метки уже вычисляется в шаблоне (по текущему статусу пользователя). Переиспользуй этот же признак, чтобы пометить активную кнопку (например, через класс/атрибут), и опирайся на него в логике подмены значения.

## Важно

- **Не менять backend** (endpoint, сервис, репозитории). Поведение «пустой status → снять» там уже есть.
- HTMX заменяет фрагмент `_status_buttons` целиком после каждого клика, поэтому любой добавленный JS должен корректно работать и **после подмены фрагмента** (то есть либо делегирование событий на стабильный родитель, либо инициализация через события HTMX, а не одноразовый `DOMContentLoaded`). Это частая ошибка — учти её.
- Сохрани доступность: метки остаются кликабельными кнопками, визуально понятно, какая выбрана.
- Минимальное вмешательство — не переписывай весь фрагмент статусов и не трогай соседний фрагмент закладок (bookmark).

## Как проверить

1. Запусти приложение, залогинься, открой страницу любой активности.
2. Кликни по метке (например «Интересно») — она становится активной, отметка сохраняется (проверяется после перезагрузки страницы).
3. Кликни по **той же** активной метке ещё раз — отметка **снимается** (метка перестаёт быть активной; после перезагрузки страницы статус пуст).
4. Поставь метку, затем кликни по **другой** метке — должна выделиться новая, статус сменился (а не снялся).
5. Убедись, что кнопки «Снять отметку» больше нет.
6. Повтори те же шаги на странице **варианта** активности — фрагмент статусов используется и там.
