# Issue #4 — Бесконечная подгрузка карточек вместо нерабочей кнопки «Показать ещё»

## Что нужно

Когда активностей больше 20, на главной появляется кнопка «Показать ещё», но **по клику ничего не происходит**. Требуется:
- Кнопки «Показать ещё» / пагинации быть не должно вообще.
- Карточки должны подгружаться по мере прокрутки (бесконечно, пока не подгрузятся все), просто удлиняя полосу прокрутки.
- Активностей немного — отдельные страницы/порционный вывод не нужны.

## Контекст и причина бага

- Главная: [CatalogController.catalog](src/main/java/com/lep/portal/catalog/CatalogController.java#L36-L66) — `GET /`, фильтры `category`/`tags`/`page`. При заголовке `HX-Request: true` возвращает фрагмент `catalog/index :: catalog-content`, иначе всю страницу.
- Пагинация: `PAGE_SIZE = 20` ([CatalogService:17](src/main/java/com/lep/portal/catalog/CatalogService.java#L17)), `getCatalogPage(...)` возвращает `CatalogPage(activities, currentPage, totalPages, totalCount)` с `hasNext()/hasPrev()`.
- Разметка карточек + пагинация: [catalog/index.html:32-87](src/main/resources/templates/catalog/index.html#L32-L87). Блок «Показать ещё»:
  ```html
  <a th:href="@{/(category=...,page=${page.currentPage()+1})}"
     class="btn-show-more" hx-get hx-target="#catalog-results" hx-swap="outerHTML">
      Показать ещё →
  </a>
  ```

**Почему не работает:** атрибут `hx-get` указан **без значения**. HTMX берёт URL из значения `hx-get`, а **не** из `href` (`href` использует только `hx-boost`). Пустой `hx-get` → запрос уходит на текущий URL без `page` → возвращается первая страница → визуально «ничего не происходит». Это корень бага.

## Подход — HTMX infinite scroll по `revealed`

> ✅ Решение зафиксировано владельцем: **вариант A** (масштабируемый, идиоматичный HTMX). Вариант «загрузить всё сразу» отклонён.

Идея: подгружать следующую порцию автоматически, когда пользователь домотал до конца текущей. Используется триггер HTMX `revealed` на «сентинеле» в конце списка.

1. **Сервер уже почти готов** — `getCatalogPage` отдаёт нужную порцию по `page`. Оставить пагинацию на бэке как есть (или увеличить `PAGE_SIZE`, например до 24/30, чтобы порции были крупнее).

2. **Фрагмент порции.** Сделать так, чтобы HTMX-ответ возвращал **только новые карточки** + новый сентинел, и они **дописывались** (`hx-swap="beforeend"`), а не заменяли весь список. Для этого:
   - Выделить в `index.html` фрагмент, рендерящий только карточки текущей страницы (`th:each` по `page.activities()`).
   - В конце списка — элемент-сентинел, который сам грузит следующую порцию:
     ```html
     <div th:if="${page.hasNext()}"
          hx-get="/?page=__${page.currentPage()+1}__(+ сохранять category/tags)"
          hx-trigger="revealed"
          hx-swap="afterend">
     </div>
     ```
     (URL формировать через `th:attr="hx-get=@{/(category=...,tags=...,page=${page.currentPage()+1})}"` — **обязательно реальным Thymeleaf-выражением**, не пустым `hx-get`.)
   - Контроллер при `HX-Request` возвращает фрагмент «порция карточек + сентинел». Сентинел текущей порции заменяется/дополняется следующей.

3. **Убрать** блок «Показать ещё»/«Назад»/счётчик страниц целиком.

4. Учесть фильтры: при подгрузке next-страницы сохранять текущие `category`/`tags` в URL сентинела (они уже есть в модели как `currentCategory`/`currentTags`).

> ⚠️ Тонкость HTMX: каждая порция должна содержать **свой** сентинел со ссылкой на следующую страницу; иначе подгрузка остановится после второй порции. Сентинел последней страницы (`!hasNext()`) не рендерится — подгрузка естественно завершается.

## Узкие места

- **Не использовать пустой `hx-get`** — корень текущего бага. Любой HTMX-URL формировать через `@{...}`.
- **Дублирование карточек / потеря сентинела** — типичная ошибка infinite scroll. Проверить, что при быстрой прокрутке не грузятся дубли и подгрузка идёт до конца.
- **Сохранение фильтров** при подгрузке (category/tags) — иначе на отфильтрованной выдаче подтянутся чужие карточки.
- `scrollbar-gutter: stable` уже задан ([main.css:49](src/main/resources/static/css/main.css#L49)) — удлинение ленты не должно дёргать раскладку (связано с #29/#30).
- Пустое состояние и состояние «одна страница» (≤ PAGE_SIZE) должны работать без сентинела.

## Что НЕ трогаем

- Фильтры по категориям/тегам (логику), они переиспользуются.
- Правый сайдбар «Что делают другие».

## Как проверить

1. На наборе > 20 активностей: прокрутка вниз автоматически подгружает следующие карточки, полоса прокрутки удлиняется.
2. Кнопки «Показать ещё»/«Назад»/счётчика страниц **нет**.
3. Подгрузка продолжается до последней карточки и затем останавливается (без бесконечных пустых запросов).
4. При выбранной категории/тегах подгружаются карточки **только** этого фильтра.
5. Нет дублирующихся карточек.
6. Набор ≤ 20 — лента показывается целиком, лишних запросов нет.
